# Бильярд-бот: рейтинг Glicko-2

Telegram-бот для закрытой компании, которая играет в бильярд друг с другом,
работает только в одном общем групповом чате. Любой участник заявляет счёт
матча прямо в группу (заявка применяется сразу, без подтверждения оппонентом)
и бот считает личный рейтинг каждого игрока по системе **Glicko-2**.

Полное ТЗ — см. приложенный файл спецификации.

## Структура проекта

```
bot/            точка входа, конфиг, polling
models/         модели SQLAlchemy (User, UserRating, Match, RatingHistory) + инициализация БД
rating/         чистая реализация алгоритма Glicko-2 (без зависимостей от БД/телеграма)
services/       бизнес-логика: пользователи, матчи, пересчёт рейтинга, аудит-лог
handlers/       обработчики команд aiogram (score, cancel, top, stats, admin, ...)
migrations/     заметки по схеме БД / переходу на Alembic+Postgres
scripts/        cron-скрипт ежедневного бэкапа SQLite
tests/          юнит-тесты модуля рейтинга (приёмочные сценарии из ТЗ)
```

## Быстрый старт

### 1. Получить токен бота

1. Напишите [@BotFather](https://t.me/BotFather) в Telegram.
2. `/newbot`, следуйте инструкциям — получите токен вида `123456:ABC-DEF...`.
3. Добавьте бота в ваш групповой чат.
4. Узнайте `chat_id` группы (например, через @RawDataBot, добавив его в
   группу временно) — **обязателен** для `GROUP_CHAT_ID`, без него бот не
   запустится.
5. Узнайте свой `telegram_id` (например, через @userinfobot) — он понадобится
   для `ADMIN_IDS`.

### 2. Настроить `.env`

```bash
cp .env.example .env
```

Заполните `BOT_TOKEN`, `GROUP_CHAT_ID`, `ADMIN_IDS` (через запятую, минимум
один человек — будущий администратор бота).

Бот работает **только в этой группе**: любые команды и кнопки вне неё
(включая личные сообщения боту) игнорируются с подсказкой писать в группу.

### 3. Запуск через Docker (рекомендуется)

```bash
docker compose up -d --build
```

База данных SQLite и логи будут сохраняться в `./data` на хосте (volume),
так что данные переживут пересборку контейнера.

### 4. Локальный запуск без Docker

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python -m bot.main
```

## Первые шаги после запуска

1. Администратор (из `ADMIN_IDS`) автоматически появляется в whitelist при
   первом старте бота.
2. Админ добавляет остальных участников: `/adduser <telegram_id> [Имя]` —
   можно узнать `telegram_id` через @userinfobot.
3. Каждый добавленный участник пишет что-нибудь в общем групповом чате
   (например `/start`) — так бот подхватит его username и имя.
4. В общем групповом чате любой участник пишет:
   `/score @игрок1 @игрок2 moscow 2:0 8:7 8:6` — результат применяется сразу,
   рейтинг обоих игроков пересчитывается немедленно, подтверждение не
   требуется.

## Команды

Полный список с описанием — команда `/faq` внутри бота. Кратко:
`/start`, `/score @игрок1 @игрок2 «тип» «счёт партий» «счёт1» [«счёт2» ...]`,
`/cancel [session_id]`, `/top [moscow|america]`, `/stats [@user]`,
`/history @user`, `/faq`, а также админские `/adduser`, `/removeuser`,
`/editmatch`.

## Рейтинг: как это работает

Реализация Glicko-2 — в `rating/glicko2.py`, строго по официальной
спецификации Марка Гликмана ("Example of the Glicko-2 system", 2013), без
внешних зависимостей. Особенности реализации:

- **Москва и Америка — два полностью независимых рейтинга** на игрока
  (таблица `user_ratings`, по строке на каждый тип игры). Партии одного
  типа не влияют на рейтинг другого — `/top` и `/stats` показывают их
  отдельно.
- Пересчёт происходит сразу после каждого `/score` (один матч = один
  рейтинговый период с одной игрой). Каждая партия внутри `/score` — свой
  собственный рейтинговый матч; для рейтинга важно только кто выиграл
  партию, счёт по шарам идёт в статистику и в `/history`.
- Перед применением результата RD игрока «подрастает» пропорционально
  времени простоя (дней с последнего матча в этом же типе игры) — учитывает,
  что давно не игравший человек мог сильно измениться в уровне.
- `/top` сортирует по консервативной оценке `rating − 2×RD` (подписана как
  Elo).
- `/editmatch` и `/cancel` вызывают полный пересчёт рейтингов всех игроков
  (по обоим типам) с нуля по истории подтверждённых матчей в хронологическом
  порядке — это самый надёжный способ гарантированно корректно пересчитать
  «всю последующую историю» после правки/отмены любого матча.

## Тесты

```bash
pip install -r requirements-dev.txt
pytest
```

Тесты (`tests/test_rating.py`) покрывают ключевые приёмочные сценарии из
ТЗ: симметричный пересчёт для двух новых игроков, малое изменение при
ожидаемом исходе, большое изменение при апсете, рост RD/скачка рейтинга
после долгого простоя, невозможность ничьей, формулу консервативной
оценки для `/top`.

## Бэкапы

`scripts/backup.sh` копирует файл SQLite в `data/backups/` с таймстампом и
хранит последние 30 копий. Добавьте в cron на сервере:

```cron
0 3 * * * /path/to/billiard/scripts/backup.sh >> /path/to/billiard/data/backups/backup.log 2>&1
```

## Логирование

Все ключевые действия (кто заявил счёт, кто отменил заявку, что изменил
админ) пишутся в `data/logs/audit.log` через `services/audit_log.py` — для
разбора спорных ситуаций постфактум.

## Whitelist и доступ

Таблица `users` одновременно служит whitelist'ом: пока админ не добавит
`telegram_id` через `/adduser`, бот игнорирует все команды этого человека
(кроме `/start`, который объясняет, что делать). Список расширяется без
правки кода — только командами `/adduser` / `/removeuser`.
