# Бильярд-бот: рейтинг Glicko-2

Telegram-бот для закрытой компании, которая играет в бильярд друг с другом.
Принимает результаты матчей, требует подтверждения от оппонента и считает
личный рейтинг каждого игрока по системе **Glicko-2**.

Полное ТЗ — см. приложенный файл спецификации.

## Структура проекта

```
bot/            точка входа, конфиг, polling, планировщик напоминаний
models/         модели SQLAlchemy (User, Match, RatingHistory) + инициализация БД
rating/         чистая реализация алгоритма Glicko-2 (без зависимостей от БД/телеграма)
services/       бизнес-логика: пользователи, матчи, пересчёт рейтинга, аудит-лог
handlers/       обработчики команд aiogram (score, confirm, top, stats, admin, ...)
migrations/     заметки по схеме БД / переходу на Alembic+Postgres
scripts/        cron-скрипт ежедневного бэкапа SQLite
tests/          юнит-тесты модуля рейтинга (приёмочные сценарии из ТЗ)
```

## Быстрый старт

### 1. Получить токен бота

1. Напишите [@BotFather](https://t.me/BotFather) в Telegram.
2. `/newbot`, следуйте инструкциям — получите токен вида `123456:ABC-DEF...`.
3. Добавьте бота в ваш групповой чат и дайте ему права отправки сообщений.
4. Узнайте `chat_id` группы (например, через @RawDataBot) — понадобится для
   `GROUP_CHAT_ID`.
5. Узнайте свой `telegram_id` (например, через @userinfobot) — он понадобится
   для `ADMIN_IDS`.

### 2. Настроить `.env`

```bash
cp .env.example .env
```

Заполните `BOT_TOKEN`, `GROUP_CHAT_ID`, `ADMIN_IDS` (через запятую, минимум
один человек — будущий администратор бота).

### 3. Запуск через Docker (рекомендуется)

```bash
docker compose up -d --build
```

База данных SQLite и логи будут сохраняться в `./data` на хосте (volume),
так что данные переживут пересборку контейнера.

### 4. Локальный запуск без Docker

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python -m bot.main
```

## Первые шаги после запуска

1. Администратор (из `ADMIN_IDS`) автоматически появляется в whitelist при
   первом старте бота.
2. Админ добавляет остальных участников: `/adduser <telegram_id> [Имя]` —
   можно узнать `telegram_id` через @userinfobot.
3. Каждый добавленный участник пишет боту `/start` в личных сообщениях —
   так бот сможет присылать ему запросы на подтверждение счёта.
4. В общем групповом чате пишем: `/score @opponent 2:0` — оппонент получит
   запрос на подтверждение в личку.

## Команды

См. таблицу команд в спецификации (раздел 4) — реализованы все пункты MVP:
`/start`, `/score`, подтверждение/оспаривание кнопками, `/cancel`, `/top`,
`/stats`, `/stats @user`, `/history @user`, `/faq`, а также админские
`/resolve`, `/adduser`, `/removeuser`, `/editmatch`.

## Рейтинг: как это работает

Реализация Glicko-2 — в `rating/glicko2.py`, строго по официальной
спецификации Марка Гликмана ("Example of the Glicko-2 system", 2013), без
внешних зависимостей. Особенности реализации:

- Пересчёт происходит сразу после подтверждения каждого отдельного матча
  (один матч = один рейтинговый период с одной игрой).
- Перед применением результата RD игрока «подрастает» пропорционально
  времени простоя (дней с последнего матча) — учитывает, что давно не
  игравший человек мог сильно измениться в уровне.
- `/top` сортирует по консервативной оценке `rating − 2×RD`.
- `/editmatch` и `/resolve` вызывают полный пересчёт рейтингов всех игроков
  с нуля по истории подтверждённых матчей в хронологическом порядке — это
  самый надёжный способ гарантированно корректно пересчитать «всю
  последующую историю» после правки/удаления любого матча.

## Тесты

```bash
pip install -r requirements-dev.txt
pytest
```

Тесты (`tests/test_rating.py`) покрывают ключевые приёмочные сценарии из
ТЗ: симметричный пересчёт для двух новых игроков, малое изменение при
ожидаемом исходе, большое изменение при апсете, рост RD/скачка рейтинга
после долгого простоя, невозможность ничьей, формулу консервативной
оценки для `/top`.

## Бэкапы

`scripts/backup.sh` копирует файл SQLite в `data/backups/` с таймстампом и
хранит последние 30 копий. Добавьте в cron на сервере:

```cron
0 3 * * * /path/to/billiard/scripts/backup.sh >> /path/to/billiard/data/backups/backup.log 2>&1
```

## Логирование

Все ключевые действия (кто ввёл счёт, кто подтвердил/оспорил, что изменил
админ) пишутся в `data/logs/audit.log` через `services/audit_log.py` — для
разбора споров.

## Whitelist и доступ

Таблица `users` одновременно служит whitelist'ом: пока админ не добавит
`telegram_id` через `/adduser`, бот игнорирует все команды этого человека
(кроме `/start`, который объясняет, что делать). Список расширяется без
правки кода — только командами `/adduser` / `/removeuser`.
